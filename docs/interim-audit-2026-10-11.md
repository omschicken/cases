Дата: 11 октября 2026 года

## Краткий результат

Проект собирается, типы проверяются, локальная PostgreSQL проходит миграции, а API отдает каталог из 93 кейсов. Основной сценарий открытия уже разделен на серверный авторизованный путь и бесплатный локальный демо-показ. В этой итерации улучшены главная страница и каталог, а продажа предмета защищена от повторного зачисления при конкурентных запросах.

Оценка готовности к реальным пользователям: **6/10**. Это оценка по четырем равным областям: сборка и данные (7/10), пользовательские сценарии (6/10), интерфейс и мобильная версия (6/10), эксплуатация и коммерческая готовность (5/10). Балл не означает готовность принимать деньги.

## Изменения в этой итерации

- Каталог стал компактнее: первоначально показываются 16 кейсов, остальные добавляются порциями по 16; поиск сбрасывает пагинацию.
- На карточках показан реальный редкий предмет из состава кейса вместо повторяющейся абстрактной обложки. Главная получила редакционный hero с предметом, доступными слайдами и учетом `prefers-reduced-motion`.
- Добавлены переводы новых элементов на RU, EN, DE, ES, PT, TR и UK.
- В `sellItem` добавлено атомарное изменение статуса предмета с проверкой количества обновленных записей. Повторная параллельная продажа не должна повторно начислить баланс. Добавлен тест гонки.
- Токены Steam callback перенесены из query string во fragment; страница callback удаляет fragment из адресной строки до последующего запроса.

## Что готово в продукте, а что еще нет

- Есть каталог и детали кейса, профиль, инвентарь, проверка честности, вход через Steam OpenID, а также страницы игровых механик и административной части.
- Серверный результат открытия использует проверяемые seed/nonce; гостевая прокрутка является демонстрацией и не создает выигрыш.
- Платежные, выводные и KYC-адаптеры остаются mock. Реальные платежи/вывод нельзя включать до интеграции лицензированного провайдера, юридической проверки и проверки всей цепочки транзакций.
- Каталог содержит 93 кейса; часть пользовательских кейсов и обложек создана как демонстрационный контент. Перед публичным запуском нужно подтвердить названия, цены, шансы, источники изображений и соответствие актуальному игровому каталогу.
- Токены авторизации сейчас хранятся в `localStorage`. Это повышает последствия XSS; перед production стоит оценить переход на защищенную `HttpOnly` cookie-сессию и проверить CSRF-модель.
- Для добавленной фичи пока нет полноценного набора browser/component тестов. Не выполнялись Lighthouse/Web Vitals, нагрузочное тестирование и независимый security review.

## Инфраструктура и следующие шаги

1. Проверить в GitHub Actions успешный production seed на правильной ветке и с актуальным `SUPABASE_DATABASE_URL`. Скриншоты показывали, что в качестве default branch используется `claude/cs2-case-opening-site-0k0i3z`; `main` в списке веток GitHub не было. Поэтому выбирать `main` в форме ручного запуска не нужно.
2. После подтвержденного seed один раз проверить Vercel сборку и запросы `/api/health` и `/api/cases`. Не запускать повторные публикации для обычной локальной разработки.
3. Проверить все ключевые маршруты в desktop/mobile, включая вход Steam, кейс, профиль, инвентарь, verify, игровые страницы и административные права.
4. Добавить веб-тесты для поиска/пагинации, экранов авторизации и демо-пути; добавить DB-backed тесты для открытия кейса, обновления инвентаря и повторных запросов.
5. После этого решать вопрос реальных платежей отдельно. До такой интеграции оставить открытие для гостей демонстрационным и не показывать фиктивное денежное действие.

### Production-проверка 12 октября

- Vercel deployment для `cases-x18t` на коммите `326b1c0` имеет статус `READY`. Текущие локальные коммиты (`396bbdc`, `1863720`) туда не публиковались.
- `https://cases-x18t.vercel.app/api/health` вернул HTTP 200, но эта проверка намеренно обходится без подключения к базе. `https://cases-x18t.vercel.app/api/cases` вернул HTTP 500 с `FUNCTION_INVOCATION_FAILED`.
- Runtime-лог Vercel установил конкретную причину: Prisma `P1000`, неверные учетные данные для Supabase на `aws-0-eu-west-1.pooler.supabase.com`. Успех GitHub Actions seed показывает, что секрет workflow и переменная Vercel `DATABASE_URL` сейчас различаются. Здоровье API нельзя считать подтвержденным до успешного запроса каталога.
- В Vercel переменные `DATABASE_URL` и `DIRECT_URL` присутствуют для Production и Preview, но метаданные не показывают их обновления после первоначального задания. Значения секретов не читались и не заносились в репозиторий.
- Для восстановления нужно заменить Vercel `DATABASE_URL` на актуальную полную URI, уже работающую в GitHub Actions. После сохранения переменной требуется ровно один новый production deployment, затем повторная проверка `/api/cases`. `DIRECT_URL` следует сверить перед будущими миграциями. До исправления конфигурации публикация кода не восстановит каталог.
